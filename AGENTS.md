# Инструкции для AI-архитектора

## Проект
- ZAPTUT.PRO — агрегатор автозапчастей с CRM.
- Стек и фактическую архитектуру определяй по текущему коду и конфигурации проекта. Документы могут описывать целевое состояние, которое ещё не реализовано.

## Работа с изменениями
- В начале каждой задачи изучи актуальные `docs/PROJECT-STATE.md` и `docs/AI-LOG.md`.
- До любых изменений проверь `git status`. Не перезаписывай, не удаляй и не включай в свои изменения чужую незакоммиченную работу.
- Самостоятельно изучи необходимые исходники, конфигурацию, документацию и тесты; не делай выводы о коде только по описаниям.
- Если требования однозначны, выполняй задачу без промежуточных вопросов.
- При противоречии требований, риске потери данных или неоднозначном бизнес-правиле остановись и запроси решение до зависимых изменений.
- До изменения изучи связанные компоненты, типы, хранилища и тесты.
- Меняй только относящиеся к задаче области; не затрагивай несвязанные разделы.
- Не удаляй и не сбрасывай демоданные.
- Не меняй утверждённые финансовые формулы без отдельного согласования.
- Не выполняй опасные операции с Git, файлами или данными без согласования.
- При обнаружении ошибки сначала опиши её причину и последствия.

## Проверки и отчёт
- После изменений запускай подходящие тесты, `npx tsc --noEmit` и `npm run build`, если эти проверки уместны для задачи.
- Если собственные изменения привели к ошибкам проверок, исправляй их и повторяй проверки до корректного результата либо зафиксируй конкретную блокирующую причину.
- Не заявляй о проверках, которые фактически не выполнялись; указывай результаты и пропущенные проверки.
- Не утверждай, что проверялся браузерный сценарий, если запускались только unit-тесты или статические проверки.
- Используй единый статус задачи: `DONE` — реализация и требуемые проверки завершены; `PARTIAL` — выполнена часть задачи; `BLOCKED` — работа остановлена из-за проблемы или необходимости решения; `NOT VERIFIED` — код изменён, но требуемый сценарий не проверен. Применяй статус к задаче целиком и поясняй непроведённые проверки.

## Журнал и состояние проекта
- Записывай каждую задачу в `docs/AI-LOG.md`: дату, задачу, изученные и изменённые файлы, решения, результаты тестов, оставшиеся проблемы и статус.
- Поддерживай `docs/PROJECT-STATE.md` только подтверждёнными сведениями; непроверенное помечай «не проверено».
- После завершения каждой задачи обновляй `docs/AI-LOG.md`, `docs/PROJECT-STATE.md` и `docs/AI-HANDOFF.md`, указывая фактические изменения, проверки, открытые проблемы и актуальный статус.
- Не создавай коммиты, не отправляй изменения в GitHub и не выполняй `git push` без отдельного разрешения.
