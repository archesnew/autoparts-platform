# Перенос ZAPTUT.PRO на другую платформу

Эта инструкция описывает перенос исходного проекта и подготовку окружения. Конкретная целевая платформа не задана, поэтому в проект не добавлена конфигурация конкретного облачного хостинга.

## Состав переносимого пакета

Архив `zaptut-pro-transfer-YYYY-MM-DD.zip` содержит исходный код приложения, публичные статические файлы и бренд-ассеты, документацию, Prisma schema и миграции, скрипты, Docker Compose, npm-манифесты и безопасный шаблон `.env.example`.

В архив намеренно не входят:

- `.env` и любые реальные секреты;
- `.git` и Git-история (текущее рабочее дерево не имеет подтверждённой истории изменений);
- `node_modules`, `.next`, `out` и TypeScript build cache — зависимости и сборку нужно создать заново;
- данные PostgreSQL из Docker volume `zaptut_postgres_data`;
- `localStorage` браузера и локальные демонстрационные изменения CRM.

Поэтому архив переносит приложение, но не пользовательские данные, учётные записи или содержимое локальной базы.

## Подготовка новой среды

1. Распакуйте архив в каталог проекта.
2. Установите Node.js версии 20.9 или новее и npm.
3. Скопируйте `.env.example` в `.env` и задайте значения через локальные переменные/секреты целевой платформы. Не отправляйте `.env` в Git и не вставляйте секреты в чаты.
4. Укажите `DATABASE_URL` для отдельной PostgreSQL. Для локальной разработки Compose-файл ожидает `POSTGRES_PASSWORD`; Compose публикует PostgreSQL только на loopback `127.0.0.1:5432` и сохраняет файлы БД в named volume.
5. Сформируйте уникальный `BETTER_AUTH_SECRET` длиной не менее 32 символов и задайте корректный `BETTER_AUTH_URL` для нового адреса приложения.
6. Установите зависимости и Prisma Client:

   ```bash
   npm ci
   npx prisma generate
   ```

7. Создайте пустую целевую PostgreSQL и примените включённые миграции:

   ```bash
   npx prisma migrate deploy
   ```

8. Создайте первого администратора только после безопасной настройки БД и секретов. Скрипт читает `ZAPTUT_ADMIN_EMAIL`, `ZAPTUT_ADMIN_NAME` и `ZAPTUT_ADMIN_PASSWORD` из локальной среды; пароль не передавайте как аргумент командной строки и не записывайте в файлы проекта.
9. Проверьте приложение:

   ```bash
   npx prisma validate
   npx tsc --noEmit
   npm run build
   npm start
   ```

`/api/health` проверяет доступность БД. Этот маршрут не подтверждает перенос CRM-данных.

## Перенос базы данных

Текущий пакет не содержит дампа PostgreSQL. Перед переносом реальных данных нужно отдельно сделать резервную копию исходной базы и проверить её восстановление в целевой среде. Не подключайте исходный Docker volume к удалённой платформе и не считайте локальную базу доступной целевому приложению. Перед реальным переходом требуется согласовать окно переноса, остановку записей, проверку целостности и план возврата.

Данные CRM в браузерном `localStorage` не мигрируются автоматически и не включены в этот архив. Их экспорт/импорт требует отдельной задачи с проверкой состава данных и резервной копией.

## Что зависит от выбранной платформы

После выбора хостинга следует отдельно определить способ запуска Next.js, настройку домена и TLS, размещение PostgreSQL, передачу секретов, резервное копирование, логи и проверки доступности. Docker Compose подготовлен для локальной разработки; сам по себе он не является конфигурацией production-развёртывания.

В проекте пока нет подтверждённых интеграций поставщиков, платёжных систем, доставки или почты. Архив не подключает и не конфигурирует эти сервисы.
