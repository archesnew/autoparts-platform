# ZAPTUT.PRO — РЕГЛАМЕНТ РЕЗЕРВНОГО КОПИРОВАНИЯ И ВОССТАНОВЛЕНИЯ БАЗЫ ДАННЫХ

## 1. Стратегия защиты данных
Платформа ZAPTUT.PRO использует двухуровневую систему отказоустойчивости и защиты PostgreSQL:

1. **Мгновенные снимки и ветки Neon (Point-in-Time Recovery):**
   - Технология Copy-on-Write хранилища Neon позволяет создавать моментальные изолированные ветки (`branch`) и откатываться к любому LSN/моменту времени в пределах retention window (6 часов на бесплатном тарифе, 30 дней на Scale/Business).
   - **Важно:** Ветка Neon находится в той же инфраструктуре AWS и защищает от логических ошибок кода/пользователей, но **не заменяет независимый оффлайн-бэкап**.

2. **Автономные логические дампы (Logical Dumps):**
   - Регулярный экспорт схемы и данных скриптом `scripts/backup-database.mjs` или утилитой `pg_dump`.
   - Хранение архивов во внешнем защищённом объектом хранилище (S3/Cloudflare R2/Yandex Object Storage) вне контура БД с шифрованием.

---

## 2. Расписание и регламент (Production target)
* **Ежедневный полный дамп (Full Daily Dump):** каждые сутки в 03:00 МСК в часы минимальной нагрузки.
* **Глубина хранения (Retention Policy):**
  - Ежедневные дампы: хранить 14 дней.
  - Еженедельные дампы: хранить 2 месяца.
  - Ежемесячные дампы: хранить 1 год.

---

## 3. Процедура аварийного восстановления (Disaster Recovery)

### Сценарий А. Быстрый откат через Neon Branch (при повреждении таблиц):
1. В панели Neon создать новую ветку `recovery-[timestamp]` от родительской ветки на момент времени до сбоя.
2. Проверить целостность данных в ветке восстановления.
3. Переключить строку подключения `DATABASE_URL` на новую ветку в переменных окружения Netlify.
4. Проверить доступность CRM и запустить `/api/health`.

### Сценарий Б. Восстановление из автономного дампа:
1. Подготовить целевую чистую БД PostgreSQL.
2. Применить схему: `npx prisma db push` или накатить SQL-схему.
3. Запустить скрипт восстановления из JSON-дампа в целевую базу.
4. Выполнить проверку консистентности: количество пользователей, заявок, заказов.

## 4. Требования к коммерческому запуску (Блокеры владельца)
* Для автоматической отправки дампов в S3 требуется настроить бакет (например, Cloudflare R2 или Yandex Cloud Object Storage) и добавить секреты:
  - `BACKUP_S3_BUCKET`
  - `BACKUP_S3_ACCESS_KEY`
  - `BACKUP_S3_SECRET_KEY`
  - `BACKUP_S3_ENDPOINT`
